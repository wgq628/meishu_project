# 桥生命周期管理协议 — Bridge Lifecycle Protocol

> 创建：2026-05-24 | v1.0 | 昆仑系统
> 用途：定义桥的状态转换规则和桥下属学科的全生命周期管理。
> 合规：本文件严格遵循 `eleven-bridges/NOMENCLATURE.md` 的命名规范。

---

# §1 桥生命周期（Bridge Lifecycle）

## 1.1 桥的四态定义

```
                  未激活（注册但无学科）
                        │
                    挂载首学科
                        │
                        ▼
     ┌─────────── 活跃 🟢 ────────────┐
     │  已有学科可参与分析             │
     └───────────┬───────────────────┘
                 │
           连续30天未被激活
                 │
                 ▼
     ┌─────────── 冻结 🟡 ────────────┐
     │  不自动参与学科桥决策树的桥域选择  │
     │  元认知自检标记                 │
     │  可手动解冻                    │
     └───────────┬───────────────────┘
                 │
           冻结状态持续90天
                 │
                 ▼
     ┌─────────── 档案 🔴 ────────────┐
     │  移出活跃索引                   │
     │  仅保留存档                    │
     │  不参与学科桥决策树的桥域选择    │
     │  可手动恢复                    │
     └───────────────────────────────┘
```

## 1.2 状态转换表

| 当前状态 | 转换条件 | 目标状态 | 自动/手动 | 说明 |
|---|---|---|---|---|
| **未激活** | 桥下挂载了第1门学科（通过预审） | **活跃🟢** | 自动 | 学科归桥即激活 |
| **活跃🟢** | 连续30天在学科桥决策树的桥域选择中未被选中 | **冻结🟡** | 自动 | 元认知自检时触发 |
| **活跃🟢** | 桥下所有学科被移除/归档 | **未激活** | 自动 | 学科为空时回退 |
| **冻结🟡** | 冻结超过90天 | **档案🔴** | 自动 | 元认知自检时触发 |
| **冻结🟡** | 手动解冻（乾坤或高权限操作） | **活跃🟢** | 手动 | 解冻后桥置信度不变 |
| **档案🔴** | 手动恢复 | **活跃🟢** | 手动 | 恢复后桥置信度维持原值 |
| **档案🔴** | 档案超过365天 | **废弃⚫** | 手动确认 | 需乾坤确认 |

## 1.3 桥置信度自动重算

| 触发事件 | 重算规则 |
|---|---|
| 桥下核心学科信度升级（T3→T2或T2→T1） | 立即重算：min(T1, 新信度) |
| 桥下核心学科被移除 | 取剩余核心学科最高信度重算 |
| 桥下新增核心学科 | 取新旧最高信度重算 |
| 辅助学科变更 | 不影响桥置信度，更新"桥下有T3学科"标注 |

## 1.4 T2桥的维护约束

桥置信度为T2或T3的桥，其推理产出在昆仑枢机中使用时需遵守：

| 桥置信度 | 使用纪律 |
|---|---|
| **T1** | 可直接作为推理依据，无需额外声明 |
| **T2** | 可直接作为推理依据，需标注引用来源 |
| **T3** | 可以引用和讨论，**不能**作为推理依据 |
| **—**（缺口桥） | 不参与桥选，不提供推理依据 |

# §2 学科生命周期（Discipline Lifecycle）

## 2.1 学科七态定义

```
                   新学科识别
                        │
                    ┌───┴───┐
                    │ 候选 🟡│
                    │ (待预审)│
                    └───┬───┘
                        │ 通过预审
                        ▼
                    ┌───────┐
                    │ 挂载 🟡│ ← 初始T3状态
                    │        │
                    └───┬───┘
                        │ 完成≥1次实战调用
                        ▼
                    ┌───────┐
                    │ 活跃 🟢│
                    │        │
                    └───┬───┘
                       ╱ ╲
          连续30天未调用 ╱   ╲ 发现重大反例/过时
                     ╱       ╲
                    ▼         ▼
             ┌────────┐  ┌────────┐
             │ 休眠 🟡│  │ 冻结 🔴│
             │ 不自动激活│  │ 不可激活│
             │ 可手动激活│  │ 标记疑点│
             └────┬───┘  └────┬───┘
                  │ 休眠60天   │ 确认过时
                  ▼           ▼
             ┌────────┐  ┌────────┐
             │ 归档 ⚪│  │ 弃用 ✖│
             │ 索引留底│  │ 完全移除│
             │ 可恢复  │  │ 不可恢复│
             └────────┘  └────────┘
```

## 2.2 状态转换表

| 当前状态 | 转换条件 | 目标状态 | 自动/手动 | 说明 |
|---|---|---|---|---|
| **候选🟡** | 通过预审（部门匹配+哲学概括性测试+交叉验证） | **挂载🟡** | 自动 | 预审由元认知自检执行 |
| **候选🟡** | 被预审否决（未通过哲学概括性测试） | **归档⚪** | 自动 | 记录原因作参考 |
| **挂载🟡** | 完成≥1次实战调用（桥选激活后被使用） | **活跃🟢** | 自动 | 分析闭环后状态升级 |
| **活跃🟢** | 连续30天未被桥激活命中 | **休眠🟡** | 自动 | 元认知自检时触发 |
| **休眠🟡** | 休眠超过60天 | **归档⚪** | 自动 | — |
| **休眠🟡** | 手动激活 | **活跃🟢** | 手动 | 激活后最后调用时间更新 |
| **活跃🟢/挂载🟡** | 发现重大反例/被新理论取代 | **冻结🔴** | 手动 | 需记录反例原因 |
| **冻结🔴** | 确认过时/错误 | **弃用✖** | 手动 | 需乾坤确认 |
| **冻结🔴** | 反例被后续分析化解 | **活跃🟢** | 手动 | 需重新挂载验证 |
| **归档⚪** | 手动恢复 | **挂载🟡** | 手动 | 恢复后重新进入挂载状态 |

## 2.3 学科归桥准入标准

每门学科归入桥前需通过**三项预审**：

### 标准1：部门匹配

```
知识所属学科 → 对应哪个科学技术部门
硬约束：
  - 系统动力学 → 系统科学 → 只能归 Q04（系统论）
  - 不跨部门（除非能提供"跨部门双重属性"的书面说明）

判定方法：
  - 知识在学科图谱（kunlun-pivot-essentials.md §2.2）中的位置
  - 如不在学科图谱中 → 按钱学森科学技术部门分类体系定位
```

### 标准2：哲学概括性测试

```
考察内容：该知识是"部门内的普遍规律"还是"具体工程技术"？

判断规则：
  - 普遍规律 → ✅ 可归桥
    - 熵增原理 → 自然科学的普遍规律 → ✅ 归Q01
    - 边际效用递减 → 经济学普遍规律 → ✅ 归Q02
  - 具体技术 → ❌ 不归桥
    - Python列表排序 → 工程技术 → ❌
    - SQL优化技巧 → 软件工程 → ❌
  - 边界模糊 → 标注"边界知识"，进入观察期
  
根本判断标准：该知识能否脱离具体技术/场景独立解释，并且在其他部门也适用？
```

### 标准3：交叉验证

```
仅跨桥归属时需要此标准：

  - 如果学科可跨多座桥（如系统韧性→Q01+Q04）：
    ① 在每座桥下独立验证该知识的适用场景
    ② 标注主桥（第一归属）和辅桥（次要归属）
    ③ 跨桥归属不超过3座
    ④ 跨桥时需注明："此学科在Q04下的使用边界不同于Q01"
    
  - 如果学科只归属一座桥 → 跳过此步
```

## 2.4 学科档案字段

每门学科归桥后，在 `registry.md` 各桥的"下辖学科"表中必须包含完整档案：

| 字段 | 示例 |
|---|---|
| 学科名称 | 系统科学·OCGS |
| 信度等级 | T1 |
| 所属桥 | Q04（系统论）[主] / Q01（自然辩证法）[辅] |
| 归桥日期 | 2026-05-24 |
| 最后调用日期 | 2026-05-24（首次注册=归桥日期） |
| 实战验证次数 | 7 |
| 最近三次调用来源 | 分析名称列表 |
| 在该桥下的核心贡献 | 系统边界界定 / 回路拆解与基模匹配 / 涌现判定 |
| 反例/失效记录 | 边界模糊时失效（已验证×3次） |
| 状态 | 活跃🟢 |

## 2.5 学科信度升级流程

从T3→T2（在桥视角下的升级条件）：

| 条件 | 说明 |
|---|---|
| ① 在桥内被实战调用≥3次 | 非孤立使用，至少3次独立分析调用 |
| ② 每次调用均有产出记录 | 通过output-packaging的存档可查 |
| ③ 通过反例生存测试 | 至少记录1个反例，证明知道适用范围边界 |
| ④ 产出与至少另一座桥产生过共振 | 证明超越单学科的跨域价值 |
| ⑤ 乾坤确认 | 最终审批 |

升级流程：

```
学科达到条件①~④
  → 元认知自检提议升级
  → 乾坤审阅
  → 确认 → 该学科在registry.md中信度更新
          → 检查是否影响桥置信度（如是核心学科→重算）
  → 否决 → 记录原因，维持当前信度
```

# §3 生命周期运维日历

## 3.1 每次分析闭环后（日维度）

由 `kunlun-output-packaging` 步骤6自动触发：

```
├── 本次激活了哪座桥的哪个学科 → 学科"最后调用日期"更新
├── 该学科"实战验证次数"+1
├── 如果学科是🟡挂载 → 检查是否为第1次激活 → 是则自动转🟢活跃
├── 缺口桥呼唤 → 检查是否有缺口桥被激活条件命中 → 呼唤次数+1
└── 各桥"最后激活"时间更新 → 桥"激活强度"判断是否需+1
```

## 3.2 每次新会话启动（会话维度）

由 `metacognitive-protocol.md` 自检流程触发：

```
桥活跃度检查：
  ├── 扫描所有桥的最后激活日期
  ├── 活跃→冻结判定：最后激活日期超过30天 → 标记冻结
  ├── 冻结→档案判定：冻结超过90天 → 归档
  ├── 缺口桥检查：呼唤次数≥3 → 标记为"待填补评估"
  └── 桥置信度审查：下辖学科是否有信度变更 → 需重算？

学科状态检查：
  ├── 候选学科 → 检查预审是否完成
  ├── 挂载→活跃判定：确认实战调用次数≥1
  ├── 休眠→归档判定：休眠超60天
  └── 冻结→弃用判定：确认过时（需乾坤确认）
```

## 3.3 每月（月维度）

由乾坤人工审查：

```
├── 桥置信度变更审查
├── T3→T2升级批量审批
├── 弃用/归档确认
├── 新学科归桥批量确认
└── 跨域映射新增/删除审查
```

## 3.4 运维日志记录格式

每次生命周期变更需记录到对应的认知日志（`memory/YYYY-MM-DD.md`）：

```
### 事件：状态变更——Q04 系统论桥/系统韧性（T3）→ 活跃🟢

- **触发条件：** P3实战（AI+老龄化）首次调用
- **操作：** 状态从"挂载🟡"→"活跃🟢"
- **验证次数：** 1
- **说明：** 首次实战调用完成，自动升级
```

# §4 学科移出条件

| 移出原因 | 判定条件 | 处理方式 | 审批 |
|---|---|---|---|
| **学科过时** | 被新理论取代，或环境变化使原失效条件被触发 | 冻结🟡→弃用✖ | 乾坤确认 |
| **误归桥** | 预审未发现跨部门问题（事后发现） | 直接移出到正确的桥 | 自动 |
| **信度不足** | T4档案知识长期（180天）无法升级T3 | 归档⚪ | 元认知标记 |
| **学科合并** | 两个学科被证明是同一事物的不同视角 | 合并为一个，删除冗余 | 乾坤确认 |
| **桥废弃** | 桥本身进入档案🔴状态 | 桥下所有学科自动解绑，回归未归位状态 | 自动 |
| **主动卸载** | 乾坤要求临时卸载某学科以测试 | 挂载🟡→归档⚪（非删除） | 乾坤指令 |
