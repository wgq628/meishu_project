# 十一桥系统 · 命名规范词典

> 创建：2026-05-24 | 步骤0 产物 | v1.0
> 用途：统一定义十一桥系统中的所有关键术语，消除语义歧义，作为所有后续文件编写的共同基准。
> 规则：本词典中的定义是**强制性规范**，所有涉及十一桥系统的文件必须严格遵循。
> 合规：本词典在乾坤审批通过后生效。任何与词典不一致的文件内容，以词典为准并应修正。

## 二、核心术语

### 2.1 桥梁 / 十一桥

| 属性 | 内容 |
|---|---|
| **定义** | 钱学森现代科学技术体系中的十一大"桥梁学科"，位于马克思主义哲学与十一大科学技术部门之间，是对应部门普遍规律与哲学概括的连接层 |
| **全称格式** | `[科技部门] → [桥梁学科]桥` 例：系统科学 → 系统论桥 |
| **编号格式** | `Q[两位编号]` 例：Q04 系统科学 → 系统论桥 |
| **所属系统** | 十一桥系统（`eleven-bridges/` 目录） |
| **存储位置** | `eleven-bridges/registry.md` |
| **数量** | Q01 ~ Q11，固定11座，不增加、不删减 |
| **禁用名称** | ❌ "联结桥" / "操作十一桥" / "方法十一桥" / "昆仑十一桥" |

### 2.2 桥梁学科 / 桥下属学科

| 属性 | 内容 |
|---|---|
| **定义** | 桥梁连接的下层科技部门的具体学科知识，是桥梁的内容基础 |
| **归属规则** | 每门学科归属到对应桥梁。可跨桥，最多3座 |
| **生命周期** | 候选→挂载→活跃→休眠→冻结→归档→弃用（详见 `lifecycle.md`） |
| **存储位置** | `registry.md` 中各桥条目的"下辖学科"字段 |
| **档案字段** | 名称 / 信度 / 主辅桥 / 归桥日期 / 最后调用 / 实战次数 / 核心贡献 / 反例记录 / 状态 |

### 2.3 桥注册表（Bridge Registry）

| 属性 | 内容 |
|---|---|
| **定义** | 十一座桥梁的形式化定义清单。每座桥包含：桥名、部门、职能、激活条件、学科归属、连接规则、推理模式、失效条件、积累库、状态 |
| **存储位置** | `eleven-bridges/registry.md` |
| **状态值** | 未激活 / 活跃🟢 / 冻结🟡 / 档案🔴（详见 `lifecycle.md`） |

### 2.4 桥积累库（Bridge Accumulation）

| 属性 | 内容 |
|---|---|
| **定义** | 每座桥梁在历次分析实战中积累的发现集合 |
| **包含** | 共振产物、新法则、约束条件、反例补充 |
| **位置** | `registry.md` 各桥条目的"已积累共鸣"字段 |
| **与"桥间共振"的区别** | 积累库是**过去的产出**存档；共振是**当前分析中**的动态交叉 |
| **增长** | 每激活一次→强度+1；每产出新积累→共鸣数+1 |

### 2.5 桥置信度（Bridge Confidence）

| 属性 | 内容 |
|---|---|
| **定义** | 桥梁的可信程度，反映其下端学科知识的整体可靠性 |
| **公式** | 桥置信度 = **min(马克思主义哲学层(T1), 桥下核心学科的最高信度)** |
| **核心学科** | 桥直接对应科技部门的**核心理论**（如系统科学→OCGS） |
| **辅助学科** | 跨桥归属的学科（如系统韧性跨Q01+Q04）→ 不影响桥置信度计算，标注"桥下有T3学科" |
| **示例** | Q04系统论桥：OCGS为T1 → 桥置信度 = min(T1, T1) = **T1** |

### 2.6 桥激活（Bridge Activation）

| 属性 | 内容 |
|---|---|
| **定义** | 学科桥决策树输出隐含激活——桥域由入口框架显化（矛盾论）直接提取，非独立选择 |
| **方向** | OS（矛盾论产出）→ 学科桥决策树（桥域定位）→ 桥层 |
| **时机** | 入口框架显化后、学科桥决策树选择时 |
| **协议** | 已由 `agent-routing-protocol.md §桥决策` 迁移至 `memory-index.md §学科方法类·学科桥决策树` |
| **消费方** | 昆仑天工OS的路由逻辑 |
| **结果** | 产生"激活桥列表"和"缺口桥列表" |

### 2.7 桥调用 / 知识请求（Bridge Invocation）

| 属性 | 内容 |
|---|---|
| **定义** | 桥激活后，桥梁向记忆系统请求知识的具体操作 |
| **方向** | 桥层 → 记忆系统 |
| **时机** | 桥激活后、开始分析前 |
| **协议** | 协议B，驻留 `eleven-bridges/bridge-memory-protocol.md` |
| **请求内容** | 学科工具、积累共鸣、历史案例、失效条件 |

### 2.8 桥间共振（Bridge-to-Bridge Resonance）

| 属性 | 内容 |
|---|---|
| **定义** | 分析过程中，多座桥的下属学科之间发生跨域碰撞，产出1+1>2的新发现 |
| **方向** | 桥↔桥横向交叉 |
| **时机** | 分析进行中（非独立协议，是内部机制） |
| **触发条件** | ①多座桥同时激活；②跨域映射匹配命中 |
| **产出** | 共振产物（新法则、约束条件、边界条件） |
| **数量纪律** | P0≤2座正式激活，跨域映射唤醒不计入上限 |

### 2.9 桥回喂（Bridge Feedback）

| 属性 | 内容 |
|---|---|
| **定义** | 分析闭环后，产出分流的过程 |
| **方向** | 分析产出 → 桥积累库 / 记忆系统 / 共鸣网络 |
| **协议** | 协议C，是 `kunlun-output-packaging` 的固定工序 |
| **分流规则** | 见协议C定义 |
| **桥状态更新** | 激活强度+1，最后激活时间更新，缺口呼唤次数+1 |

### 2.10 缺口桥（Gap Bridge）

| 属性 | 内容 |
|---|---|
| **定义** | 问题特征匹配但对应桥梁尚无学科覆盖（即"空白桥"） |
| **处理** | 标记为缺口，记录到 registry.md 的缺口桥列表，**不造假填充** |
| **填补策略** | 按实战呼唤次数排序，呼唤≥3次的高频缺口优先填补 |
| **初始缺口** | Q03数学哲学 / Q06人天观 / Q07美学 / Q10地理哲学 / Q11建筑哲学 |

## 三、独立术语（非十一桥系统）

### 3.1 共鸣点（Resonance Point，编号 RP#[N]）

| 属性 | 内容 |
|---|---|
| **定义** | 记忆系统中两个独立知识条目偶然碰撞后发现的新关联 |
| **性质** | 属于**元认知层**，记录"使用知识时的经验发现"，与十一桥完全无关 |
| **旧称** | "联结桥" / "桥#[编号]"（**废弃**） |
| **存储位置** | `resonance-net.md`（根目录，不在 `memory/` 内） |
| **置信度** | 共鸣置信度 = 两端Source信度取最低 |
| **强度** | 每被元认知激活一次 +1 |
| **与桥层的关系** | 无直接关系。桥的跨域映射/积累库 与 共鸣点 是两种独立的产出 |

### 3.2 记忆系统（Memory System）

| 属性 | 内容 |
|---|---|
| **定义** | 昆仑系统中存储和检索知识的基础设施 |
| **内容** | MEMORY.md / memory-index.md / views/ / analysis/ |
| **位置** | 根目录（MEMORY.md）+ memory/ 子目录 |
| **与桥层的关系** | 桥层是记忆系统的**消费者**（协议B拉取知识）；记忆系统是桥层的**供给方** |

### 3.3 昆仑天工 OS（Kunlun Tian Gong OS）

| 属性 | 内容 |
|---|---|
| **定义** | 昆仑系统的分析流程操作系统 |
| **组件** | 四核心算法（矛盾论/实践论/持久战/OCGS）+ 五操作模块 + 元认知协议 |
| **文件** | SOUL.md / metacognitive-protocol.md / agent-routing-protocol.md / kunlun-output-packaging |
| **与桥的关系** | 桥层是OS的学科组织引擎——OS发起调用（协议A），桥层执行知识组织（协议B/C） |

## 五、编号体系

| 编号系统 | 用途 | 范围 | 示例 |
|---|---|---|---|
| **Q01~Q11** | 十一桥系统的桥梁编号 | 固定，11个 | Q04 系统科学 → 系统论桥 |
| **RP#001~RP#N** | 共鸣点编号 | 动态增长 | RP#001 战略耐力指数 |
| **SC-001~SC-N** | 学习卡编号 | 动态增长 | SC-006 心理学·认知偏差 |
| **CL-001~CL-N** | 案例编号 | 动态增长 | CL-001 航发供应链 |

**冲突规则：**
- `Q` 前缀**仅**用于十一桥
- `RP` 前缀**仅**用于共鸣点
- 任何文件中**禁止**同时出现"Q#001"和"桥#001"指代不同事物
- 旧编号"桥#001~#010"应全部清理为"RP#001~RP#010"

## 六、文件扩展名规范

| 文件 | 用途 | 位置 | 不得 |
|---|---|---|---|
| `eleven-bridges/` | 十一桥系统全部文件 | 独立目录 | 存放记忆系统或共鸣点内容 |
| `resonance-net.md` | 共鸣点记录 | **根目录** | 存放十一桥定义或记忆知识 |
| `bridges.md`（已删除） | `resonance-net.md` 的别名（原重定向文件已清理） | 根目录 | 已清理 —— 所有引用指向 `resonance-net.md` |
| `memory/` | 知识存储 | 子目录 | 存放桥定义或共鸣网络 |
| `plans/` | 计划和设计文档 | 子目录 | 存放运行时规范 |

## 七、合规检查清单

任何涉及"桥"的新文件或修改提交前，逐项检查：

- [ ] 我写的"桥"是指钱学森十一桥梁——不是操作流程、不是共鸣点？
- [ ] 文件放在正确的目录（`eleven-bridges/` vs `memory/` vs 根目录）？
- [ ] 编号用了正确的系统（Q vs RP vs SC vs CL）？
- [ ] "桥置信度"出现在桥层文件，没有出现在记忆系统文件？
- [ ] "共鸣点"出现在共鸣网络文件，没有出现在桥层文件？
- [ ] 没有同时在两个系统中用"桥#001"这种模糊编号？
- [ ] `bridges.md` 引用已全部更新至 `resonance-net.md`？（若仍发现直接文件路径引用，改之）
- [ ] 所有旧术语对照表中的废弃名词已从本次提交的文件中清除？
