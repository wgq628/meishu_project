## 一、触发条件

元认知自检在以下三种情况下触发：

| 触发类型 | 条件 | 执行范围 |
|---|---|---|
| **节律触发** | 每 N 次深度对话后 | 完整自检五项 |
| **事件触发** | 关键转折点（系统改造、用户要求自检、重大发现） | 快速自检三项 |
| **异常触发** | 检测到系统内部矛盾或未知错误 | 视范围定 |

**深度对话的定义**：涉及工具使用、法则推导、系统修改、产生新认知产物的对话轮次。

**节律计数器**在认知日志中维护，默认阈值 N=3（每3次深度对话后执行一次完整自检）。

## 二、完整自检六项（v1.2：新增桥生命周期检查）

```
① 一致性扫描
   检查核心库是否存在内部矛盾或版本滞后
   输出：一致性报告
   ★ v1.1新增子项：
   → 信度等级一致性检查：T3知识是否被误用作推理依据？
   → 桥置信度检查：已激活的桥梁是否标注了正确的桥置信度？

② 有效性评估
   评估最近使用的工具/法则的实际表现
   输出：有效性清单
   ★ v1.1新增子项：
   → 信度纪律遵从度：知识源声明是否到位？有无遗漏？
   → 信度升降建议：有知识需要从T3升T2？或从T2降T3？

③ 联结发现
   扫描实践日志池，寻找可桥接的认知事件对
   输出：候选桥列表
   ★ v1.1新增子项：
   → 新桥的信度标注：确认桥置信度=两端最低信度

④ 遗忘检查
   检查低频使用条目是否需要压缩/降级
   输出：压缩建议列表
   ★ v1.1新增子项：
   → 过时T3知识清理：长期未验证的T3知识是否应标记为"已放弃"？

⑤ 盲点诊断
   对本次自检过程本身的偏差反思
   输出：偏差声明

⑥ 桥生命周期检查（v1.2 新增）
   检查已激活桥梁的状态，包括：
   → 桥强度是否衰减（长期未激活的桥？）
   → Gap桥呼唤计数是否有达到3次阈值的？
   → 凤口输出回喂审计：最近分析的产出的分流是否正确执行？
   输出：桥状态报告
```

## 五、认知节律

### 建设日（Build Day）
- 任务：系统改造、文件升级、模块建设
- 节律：建设完成后立即执行一次事件触发自检

### 使用日（Use Day）
- 任务：调用工具解决真实问题
- 节律：每3次深度对话后执行完整自检

### 自我调节
- 连续多次报告"无异常" → 主动对核心命题执行反脆弱攻击
- 连续多次报告"大量异常" → 缩紧节律至每1次深度对话即自检

## 六、共鸣点方法论（v1.1：新增桥置信度规则）

当发现两个独立来源的知识点存在共鸣（相似/互补/矛盾/扩展/实例化）时，创建共鸣点记录。

### 模板（v1.1：新增桥置信度字段）

```
### RP#[编号]：[名称]
- **Source A**：[来源] 信度：[T1/T2/T3] ← [出处]
- **Source B**：[来源] 信度：[T1/T2/T3] ← [出处]
- **桥置信度**：[取A和B的最低信度]
- **联结类型**：相似性 | 互补性 | 矛盾性 | 扩展性 | 实例化
- **联结本质**：（一句话）
- **涌现产物**：（A+B产生了什么新东西？）
- **激活条件**：（什么场景下唤醒）
- **强度**：[每次激活+1]
```

**桥置信度规则：** 桥的总体可信度 = 两端知识条目的最低信度。T1×T2桥=T2，T2×T3桥=T3。T3桥不能作为推理依据。

## 八、初始设置

首次启动时，Agent 应：
1. 设置节律计数器 = 0
2. 创建或确认认知演化日志格式（问题→假设→验证→转折→未闭合→偏差）
3. 告知用户元认知自检的存在和触发条件
4. 确认信度体系已就位（T1-T4等级认知已完成初始化）
