## 〇、信度体系总览

### 四级信度等级

| 等级 | 含义 | 准入条件 | 使用纪律 |
|---|---|---|---|
| **T1 绝对公理** | 永不质疑。所有推理的逻辑起点。 | 核心身份+根本立场+方法论本身 | 可直接作为推理依据，无需额外声明 |
| **T2 已验证** | 已经过实战检验，可信度高。 | 通过反例生存测试+至少1次实战+乾坤确认 | 可直接作为推理依据，需标注引用 |
| **T3 学习中** | 正在消化/待验证的新知识。不能作为推理依据。 | 无（学习材料自动进入） | **不能作为推理依据**。引用时必须声明"来自学习材料，尚未验证" |
| **T4 档案** | 历史记录。 | 分析完成自动归档 | 只能作为参考。引用时必须声明"仅作参考" |

### 信度升降规则

```
学习材料 → T3（自动进入）
   │
   ├── 通过反例生存测试
   ├── 经过至少1次实战验证
   ├── 乾坤确认
   │
   ▼
T2 已验证
   │
   ├── 跨百战检验
   ├── 成为不可动摇的认知基座
   │
   ▼
T1 绝对公理
   │
   ┌────────────────────────────────┐
   │  ⚠️ 反例推翻                    │
   │  → T1/T2 → 标记🗑️废弃假设     │
   │  → 移入T3学习库·教训区          │
   └────────────────────────────────┘
```

### 桥置信度规则

共鸣点是跨知识条目的共鸣记录。桥的总体置信度 = 两端知识条目的最低信度。

| 两端信度组合 | 桥置信度 | 能否用于推理 |
|---|---|---|
| T1 × T1 | T1 | ✅ 可直接作为推理依据 |
| T1 × T2 | T2 | ✅ 可直接作为推理依据 |
| T2 × T2 | T2 | ✅ 可直接作为推理依据 |
| T2 × T3 | T3 | ⚠️ 可用于创造性探索，不能作为推理依据 |
| T3 × T3 | T3 | ❌ 不能作为推理依据 |

### 信度声明纪律（知识源标注规则）

在昆仑枢机工作流的每一步推理中，"根据XXX"的推理依据必须明确信度等级：

```
"根据 [T1] 矛盾论·主要矛盾律 → 核心矛盾是X"   ✅ 直接推理
"根据 [T2] 防御均衡法则 → ..."                 ✅ 标注引用
"根据 [T3] 历史学·三层时间分析法 → ..."         ⚠️ 必须声明"来自学习材料"
"根据 [T4] 案例库·半导体分析 → ..."             ⚠️ 必须声明"仅作参考"
无 T1/T2 支撑的判断                               ❌ 强制声明"未经思想库验证"
```

## 一、结构化命题记录格式

所有长期记忆应以结构化命题形式记录，而非扁平叙述。

### 核心字段（v1.1：新增信度+学科字段）

```
### 命题 [编号]：[名称]

**命题表述**：（一句话，清晰、无歧义）

**信度**：[T1/T2/T3/T4]

**所属学科**：[学科名]

**所属桥**：[Q01-Q11编号]（参见十一桥桥梁学科）

**依赖链**：（这个命题依赖哪些更深层的判断？）

**反例日志**：
- 反例#1：[描述] → [是否已消化]
- ...

**失效条件**：（什么条件下这个命题会失效？）

**来源**：（来自哪次对话/分析）

**最后验证**：YYYY-MM-DD

**修正记录**：[日期] [修改者] [摘要]
```

### 信度分层说明

| 等级 | 修改门槛 | 示例 |
|---|---|---|
| **T1** | 乾坤直接授权+跨三次实战检验 | 核心立场、方法论本身 |
| **T2** | 新反例+替代方案同时出现+乾坤确认 | 已验证的工具/法则 |
| **T3** | 可直接证伪和更新 | 正在学习的学科、待验证的新假设 |
| **T4** | 不可修改（只能补充注释） | 历史分析报告、归档记录 |

## 二、记忆索引格式

所有可复用的工具/法则/流程应有索引条目，按"场景→工具"方式检索。

### 模板（v1.1：新增信度等级+所属学科字段）

```
### [工具/法则名称]
- **内容摘要**：（一句话）
- **信度**：[T1/T2/T3/T4]
- **所属学科**：[学科名]
- **所属桥**：[Q01-Q11编号]（关联十一桥桥梁学科）
- **完整指南**：[文件路径]，§章节
- **适用场景**：（什么条件下有用）
- **失效条件**：（什么条件下会失效）
- **激活条件**：（什么信号出现时应该唤醒）
- **引用次数**：[N，每次被引用+1]
- **最后验证日期**：YYYY-MM-DD
- **来源**：（来自哪次对话/分析）
```

## 三、视图层规范

同一套知识，从不同视角按信度筛选浏览。视图层不创造新的事实存储。

### 三种视图

| 视图 | 筛选条件 | 存储位置 | 用途 |
|---|---|---|---|
| **公理卡视图** (Axiom Cards) | T1知识 | `memory/views/axiom-cards-index.md` | 查看不可动摇的核心公理 |
| **桥筛选视图** (Bridge View) | **按所属桥筛选** | `memory/views/bridge-view-index.md` | 从十一桥视角检索知识条目 |
| **学习卡视图** (Study Cards) | T3知识 | `memory/views/study-cards-index.md` | 了解正在学习的学科概览 |
| **案例库视图** (Case Library) | T4知识 | `memory/views/case-library-index.md` | 查阅历史实战案例 |

### 每张卡片的核心字段

```
### [编号]：[名称]

**信度**：[T1/T2/T3/T4]

**一句话**：（10字内）

**详细定义**：（2-3句）

**适用场景**：
**失效条件**：

**所在源文件**：[文件路径]

**依赖链**：（如果有）

**创建日期**：YYYY-MM-DD
```

## 四、知识库版本号规范

### 语义化版本

```
vMAJOR.MINOR.PATCH
```

| 变动 | 数值变更 | 示例 |
|---|---|---|
| T1 核心信仰变更 | MAJOR+1 | v1.x.x → v2.0.0 |
| 新知识条目/模块加入 | MINOR+1 | v1.1.x → v1.2.0 |
| 置信度升降、反例补充、勘误 | PATCH+1 | v1.1.0 → v1.1.1 |

### 版本号存储

- **主文件**：`VERSION.md`（仅存储版本号与变更摘要）
- **详版**：`MEMORY.md` §修正记录（完整的每条变更记录）

### 发布规则

```
知识变更
    ↓
Agent提交变更卡（含版本号建议）
    ↓
用户审批 → 同意版本号
    ↓
Agent执行变更 → 更新VERSION.md + MEMORY.md修正记录
    ↓
Agent提交变更报告
    ↓
用户审阅 → 确认发布
```

## 五、认知演化日志格式

日常日志从"事件记录"改为"认知演化记录"。

### 每个认知事件包含

```
### 事件 #[编号]

- **初始问题**：触发这次认知活动的问题
- **假设**：开始时的判断
- **转折点**：什么信息改变了看法
- **废弃假设**：否定了哪些初始想法
- **产出**：最终结果
- **未闭合**：还没想透的点
- **偏差反思**：最可能犯了什么认知偏差
```

### 日志存储

- 每日日志：`memory/YYYY-MM-DD.md`
- 每个认知事件用 `### 事件 #[编号]` 标记，便于检索

## 六、初始文件结构

首次启动知识结构技能时，Agent应创建以下文件体系：

```
memory-index.md       — 工具/法则场景索引（按模板初始化）
memory/views/         — 视图层目录
  ├── axiom-cards-index.md    — 公理卡视图
  ├── study-cards-index.md    — 学习卡视图
  └── case-library-index.md   — 案例库视图
memory/YYYY-MM-DD.md  — 当日认知演化日志
anti-fragility-pool.md— 反脆弱池（核心命题的最强反例，空模板）
knowledge-tree/bridge-resonance-matrix.md  — 桥间共振矩阵
VERSION.md            — 版本号（初始 v1.0.0）
```

注意：MEMORY.md 是核心知识库，内容需通过长期与用户的对话自然生长，首次启动时不创建空文件——待积累足够命题后创建。

## 七、分发包接口（T1/T2可打包）

昆仑知识可以分层级打包分发给其他AI Agent：

| 包类型 | 包含内容 | 独立可用性 |
|---|---|---|
| **方法论包** | 四大核心算法(T1) + 五大操作模块(T1) + 信度规范(T1) | ✅ 独立可用 |
| **知识库包** | 所有T2命题 + 学科知识图谱 + 共鸣点 | ⚠️ 依赖方法论包 |
| **案例包** | T4案例库 + 反脆弱池 + 桥 | ⚠️ 依赖方法论包+知识库包 |

**打包原则：** 只打包T1和T2知识。T3和T4属于"进行中"和"归档"，一般不对新Agent下发。

## 八、种子数据（随包分发）

`kunlun-knowledge-structure` 技能包中附带初始化种子数据，方便新安装的Agent快速获得可工作的卡片示例。

### 种子数据位置

```
seed-data/
└── views/
    ├── axiom-cards-index.md    — 4张T1公理卡（矛盾论/实践论/论持久战/OCGS）
    ├── study-cards-index.md    — 3张T3学习卡（历史学/管理学/法学）
    └── case-library-index.md   — 1张T4案例卡（航发供应链韧性构建）
```

### 部署方式

安装 `kunlun-knowledge-structure` 后，Agent 应执行一次冷启动部署：

```bash
# 部署种子数据到系统的 memory/views/ 目录
cp -r seed-data/views/* ../../memory/views/
```

### 种子数据注意事项

- 种子数据是**示例**，新Agent应在其基础上自然生长自己的卡片
- T1公理卡（四大核心算法）建议保留——它们是昆仑天工的认知基座
- T3学习卡可以替换为Agent自己擅长的学科
- T4案例卡是演示用途——新Agent分析真实问题后会生成自己的案例
